# Staff sessions and private owner assignment — v0.1

User-approved September 19, 2026: `STAFF_AUTH_MODE=session` replaces the local preview's 15-minute password gate. Authorized signed-in editors/admins can edit, review, publish and use staff tools for the life of their valid session. Password/passkey recent-verification modes remain available as explicit policies; unknown configuration still fails closed to the passkey policy. Roles, saved-recovery prerequisite, recovery suspension, session-version revocation, CSRF and origin checks, optimistic revisions and audit remain. Account password/recovery-setting changes retain separate recent-sign-in protection. This removes step-up protection: a stolen active staff session can perform staff actions until revoked or expired. Use trusted devices and sign out after use.

- Entry detail and edit toolbars offer **Assign owner**, opening a Material UI dialog. Its searchable, paginated account picker accepts a selected existing account, not arbitrary text. Only authorized staff may query `/api/ownership/candidates`; it returns ID, private username and alias only, with `no-store`. Anonymous visitors and ordinary users cannot enumerate accounts.
- Account ownership remains a seven-day offer requiring recipient acceptance. Current ownership stays unchanged while pending. In session mode, acceptance uses the signed-in recipient's explicit consent without another password prompt. Existing concurrent-change, expiry, revocation, role, session and audit safeguards remain.
- **No account** permits an optional private manager alias (80 characters). Ask permission and avoid personal contact details. It grants no account access; only staff maintain the entry. Replacing a registered owner warns that their editing access will end. Pending offers must be cancelled first. The operation is version-checked and audited, clears confirmation timestamps, and changes no public content. The label lives only in staff ownership records/private history, never public listing responses. Later account acceptance clears it.
- Migration `016_external_owner.sql` adds a nullable private label and prevents combining it with account ownership. Existing entries are unchanged. Restore-content actions do not restore ownership.
- The edit form's required change reason sits immediately before Save. Ownership is a separate dialog action; save content edits before changing ownership because ownership changes create a new revision.
- Restricted-entry cards show one accessible lock beside Save, to the right of the title. Detail/table status displays retain their lock and explanatory tooltip.

This policy supersedes the recent-verification and exact-username-only discovery portions of earlier staff/ownership documents. No public release or Rosie Studio changes are included.

Local rollout: private pre-migration backup `data/backups/pre-owner-dialog-iRIx7h/database.dump`; all 284 existing entries retained with no manager labels or ownership changes applied. Disposable-schema tests cover aged-session editing, staff-only lookup, no-account privacy and audit, stale-version/CSRF rejection, recipient consent and revocation races. Browser tests cover the picker, modal keyboard access/mobile layout and the reason field before Save.
